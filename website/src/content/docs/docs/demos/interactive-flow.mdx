This demo reaches `WAITING`, persists that state, and resumes when you deliver input.

## Start the flow

```bash
skiller run --file examples/interactive-flow/flow.yaml
```

The response includes a `run_id`, the `WAITING` status, and the prompt `What is your name?`.

## Resume it

```bash
skiller input receive <run_id> --text "Ada" --wait
```

The same run resumes, emits `Hello, Ada!`, and reaches `SUCCEEDED`.

## What this proves

Waiting is persisted rather than simulated in memory. The process that started the run does not need to remain attached while the workflow waits.
